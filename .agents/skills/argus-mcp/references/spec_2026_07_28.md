**Standard Governance:** Open Source Model Context Protocol Working Group

## 1. Overview & Architectural Evolution

The **2026-07-28** specification of the Model Context Protocol represents the most significant architectural evolution since the standard's inception in November 2024. The release transitions MCP from a stateful, connection-oriented RPC protocol to a **stateless request/response standard** designed for cloud-native, horizontally scalable AI agent architectures.

### Chronological Version History

| Spec Version | Date | Key Architectural Additions | Lifecycle Paradigm |
| :--- | :--- | :--- | :--- |
| `2024-11-05` | Nov 2024 | Initial public standard; stdio & SSE transports; bidirectional JSON-RPC 2.0. | **Stateful**: Mandatory `initialize` → `notifications/initialized` handshake. |
| `2025-03-26` | Mar 2025 | Extended error payloads; structured root URI normalization. | **Stateful**: Session tracking with sticky connections. |
| `2025-06-18` | Jun 2025 | Structured content return types (`structuredContent`); pagination tokens. | **Stateful**: Client session persistence. |
| `2025-11-25` | Nov 2025 | Full JSON Schema 2020-12 adoption for tool arguments; OAuth 2.0 metadata hints. | **Stateful**: Handshake-locked sessions. |
| **`2026-07-28`** | **Jul 2026** | **Stateless Request/Response Core**; `_meta` self-describing requests; `server/discover` RPC; SEP-2322 MRTR; Response Caching. | **Stateless**: Zero mandatory initialization; requests are completely independent. |

## 2. Wire Format & JSON Schemas

### 2.1 Per-Request Metadata (`_meta`)

In version `2026-07-28`, every request is self-describing. Clients include protocol information inside the `_meta` parameter object:

```json
{
  "jsonrpc": "2.0",
  "id": "req-101",
  "method": "tools/call",
  "params": {
    "name": "argus_scan",
    "arguments": {
      "dirs": ["internal/db"]
    },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientInfo": {
        "name": "ArgusClient",
        "version": "1.4.0"
      },
      "io.modelcontextprotocol/clientCapabilities": {
        "tools": {}
      }
    }
  }
}
```

### 2.2 Upfront Discovery RPC (`server/discover`)

Clients may query server capabilities and supported protocol versions without initiating a session:

**Request:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "server/discover"
}
```

**Response (`DiscoverResult`):**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "resultType": "complete",
    "protocolVersions": [
      "2024-11-05",
      "2025-03-26",
      "2025-06-18",
      "2025-11-25",
      "2026-07-28"
    ],
    "supportedVersions": [
      "2024-11-05",
      "2025-03-26",
      "2025-06-18",
      "2025-11-25",
      "2026-07-28"
    ],
    "capabilities": {
      "tools": {
        "listChanged": false
      }
    },
    "serverInfo": {
      "name": "argus",
      "version": "v1.2.0"
    },
    "_meta": {
      "io.modelcontextprotocol/serverInfo": {
        "name": "argus",
        "version": "v1.2.0"
      }
    }
  }
}
```

### 2.3 List Tools with Cache Metadata (`tools/list`)

Servers can return TTL and cache scoping hints to prevent redundant tool lookups:

**Response:**
```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "tools": [
      {
        "name": "argus_scan",
        "description": "Database safety auditor for Go and PostgreSQL.",
        "inputSchema": {
          "type": "object",
          "properties": {
            "dirs": { "type": "array", "items": { "type": "string" } }
          }
        }
      }
    ],
    "_meta": {
      "ttlMs": 300000,
      "cacheScope": "workspace"
    }
  }
}
```

## 3. SEP-2322: Multi Round-Trip Requests (MRTR)

In stateful protocols, asking the human for permission or confirmation required long-running sessions or reverse RPC calls (`sampling/createMessage`). In `2026-07-28`, **SEP-2322** formalizes stateless multi-turn interactions:

### Turn 1: Server Requires Input
```json
{
  "jsonrpc": "2.0",
  "id": 10,
  "result": {
    "resultType": "input_required",
    "requestState": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "inputRequests": [
      {
        "id": "confirm_migration",
        "type": "confirmation",
        "message": "Destructive column drop detected on table 'users'. Confirm execution?"
      }
    ]
  }
}
```

### Turn 2: Client Submits Input Resuming Execution
```json
{
  "jsonrpc": "2.0",
  "id": 11,
  "method": "tools/call",
  "params": {
    "name": "argus_check_migration",
    "arguments": {
      "sql": "ALTER TABLE users DROP COLUMN email;"
    },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28"
    },
    "requestState": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "inputResponses": {
      "confirm_migration": true
    }
  }
}
```

## 4. Standard Error Codes Specification

| Code | Constant | Meaning in MCP 2026-07-28 |
| :--- | :--- | :--- |
| `-32700` | `CodeParseError` | Invalid JSON syntax encountered by transport scanner. |
| `-32600` | `CodeInvalidRequest` | JSON-RPC structural violation (e.g. duplicate keys, non-2.0 version). |
| `-32601` | `CodeMethodNotFound` | Unrecognized method name. |
| `-32602` | `CodeInvalidParams` | Argument or schema validation error; unsupported version in `_meta`. |
| `-32603` | `CodeInternalError` | Unexpected server panic or catastrophic system fault. |
| `-32002` | `CodeServerNotInitialized` | Legacy 2024-11-05 request sent prior to `initialize` completion. |
| `-32022` | `CodeUnsupportedProtocolVersion` | Dedicated error indicating the requested protocol version is not offered. |
| `-32800` | `CodeCancelled` | Client sent `notifications/cancelled` targeting an in-flight request. |
